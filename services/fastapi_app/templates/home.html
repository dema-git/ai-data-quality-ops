Pipeline overview

  1. A data generator (Faker) creates synthetic user sessions and events.
  2. A Kafka producer sends these events to a raw Kafka topic.
  3. A Kafka consumer writes all incoming events as Bronze Parquet files into MinIO storage.
  4. The Airflow ETL pipeline transforms Bronze → Silver → Gold: - cleans raw data - standardizes schemas - normalizes nested fields - produces analytical Gold tables
  5. Every transformation writes an outbox metadata record (file name, rows, bucket, status).
  6. A dedicated Archive DAG moves processed Bronze/Silver/Gold files into archive buckets.
  7. A Cleanup DAG removes archived files permanently from MinIO.
  8. The FastAPI Analytics API exposes aggregated metrics and pipeline information.
  9. The monitoring UI shows live ETL metrics, file counts, and system status using HTMX.
  10. The AI ops layer will use structured quality reports to summarize incidents and suggest next checks.
  11. All logs are structured JSON and collected by Grafana / Prometheus / Loki for full observability.
